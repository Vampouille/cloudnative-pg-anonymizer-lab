Goal: Deploy a 3-instance PostgreSQL cluster managed by CloudNativePG, explore the created resources and test failover.
1. Create a cluster

In a new folder, create a lab1.yaml file with:

apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: prod
spec:
  instances: 3
  storage:
    size: 2Gi

Deploy the manifest:

kubectl apply -f lab1.yaml
Note: The installation of Cloud Native PG is mantory before deployment of your first cluster.
2. Inspect Kubernetes objects
kubectl get pod,service,secret,pvc -l "app.kubernetes.io/managed-by=cloudnative-pg"
3. Check cluster status
kubectl get cluster
kubectl cnpg status prod # check timeline: 1
4. Connect to the cluster
kubectl cnpg psql prod
5. Kill replica or primary
kubectl delete pod prod-3 # kill a replica

kubectl delete pod prod-1 # kill the primary
kubectl cnpg status prod  # notice timeline increment: 2

# Kill all cluster pods
kubectl delete pod -l "app.kubernetes.io/managed-by=cloudnative-pg"

Goal: Deploy a cluster with the PostgreSQL Anonymizer extension and define masking rules on sensitive data.
1. Inspect ClusterImageCatalog
kubectl describe clusterimagecatalog
2. Clean up the previous cluster
kubectl delete cluster prod
3. Deploy a new cluster with PostgreSQL Anonymizer

Create a file prod-anon.yaml:

---
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: prod
spec:
  instances: 3
  imageCatalogRef:
    apiGroup: postgresql.cnpg.io
    kind: ClusterImageCatalog
    name: camptocamp
    major: 18
  postgresGID: 999 # initdb: could not look up effective user ID 26: user does not exist
  postgresUID: 999
  postgresql:
    pg_hba:
      - host all all all trust
      - host replication all all trust
  storage:
    size: 2Gi
  bootstrap:
    initdb:
      postInitSQL:
        - |
          ALTER DATABASE postgres
            SET session_preload_libraries = 'anon';
          CREATE EXTENSION anon;
          ALTER DATABASE postgres
            SET anon.transparent_dynamic_masking TO true;
kubectl apply -f prod-anon.yaml
4. Create a people table
kubectl cnpg psql prod
CREATE TABLE people AS
    SELECT  153478       AS id,
            'Sarah'      AS firstname,
            'Conor'      AS lastname,
            '0609110911' AS phone;
5. Define masking rules
SECURITY LABEL FOR anon ON COLUMN people.lastname
  IS 'MASKED WITH FUNCTION anon.dummy_last_name()';

SECURITY LABEL FOR anon ON COLUMN people.phone
  IS 'MASKED WITH FUNCTION anon.partial(phone,2,$$******$$,2)';
6. Create a masked user
CREATE ROLE skynet LOGIN;

SECURITY LABEL FOR anon ON ROLE skynet IS 'MASKED';

GRANT pg_read_all_data to skynet;
7. Connect with the skynet role
kubectl cnpg psql prod -- -h localhost --username skynet postgres
Note: The local policy in pg_hba.conf is managed by CNPG so peer connection cannot be used for the skynet role.
8. Inspect data
TABLE people;

Goal: Create a new cluster bootstrapped from a pg_dump with a masked role.
1. Create the cluster definition

Create a lab3.yaml file with a new Cluster definition compatible with PostgreSQL Anonymizer:

apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: prod-copy-green
spec:
  instances: 1
  storage:
    size: 2Gi
  imageCatalogRef:
    apiGroup: postgresql.cnpg.io
    kind: ClusterImageCatalog
    name: camptocamp
    major: 18
  postgresGID: 999 # initdb: could not look up effective user ID 26: user does not exist
  postgresUID: 999
2. Inspect services of the prod cluster

Because pg_dump needs to acquire a lock, we will use the prod-rw endpoint. We will use the masked role skynet for data extraction.

kubectl get service -l 'cnpg.io/cluster=prod'
3. Add the externalClusters section
  externalClusters:
    - name: prod
      connectionParameters:
        host: prod-rw
        user: skynet
        dbname: postgres
4. Add the bootstrap section
  bootstrap:
    initdb:
      import:
        type: monolith
        databases:
          - postgres
        source:
          externalCluster: prod
        pgDumpExtraOptions:
          - --no-owner
          - --no-privileges
Tip: The pg_dump options ensure that there are no errors related to missing roles.
5. Deploy the cluster
kubectl apply -f lab3.yaml
kubectl get pod --watch

A prod-copy-green-init pod is responsible for launching initdb and then pg_dump/pg_restore.

6. Connect to the cluster
kubectl cnpg psql prod-copy-green
7. Search for personally identifiable information
TABLE people;
Note: Using the pg_dump method, unlike previous lab, the data are now stable.

Goal: Create a standalone replica cluster of prod, promote the cluster and apply static masking.
1. Inspect replication secrets created by the prod cluster
kubectl get secret -l app.kubernetes.io/managed-by=cloudnative-pg
  • prod-app – credentials for the app role (user, password, URI)
  • prod-ca – certificate authority for servers and certificate-based roles
  • prod-server – server certificate
  • prod-replication – certificate for streaming replication authentication
2. Try a connection with the default application role app
export PROD_APP_URI=$(kubectl get secret prod-app -o jsonpath='{.data.uri}' | base64 -d)
echo ${PROD_APP_URI}
kubectl run psql --rm -it --image=ghcr.io/camptocamp/postgres:18 --restart=Never -- psql $PROD_APP_URI
3. Inspect the replication secret
kubectl get secret prod-replication -o yaml
4. Create the replica cluster

Create a file lab4.yaml:

---
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: prod-copy-blue
spec:
  instances: 1
  storage:
    size: 2Gi
  imageCatalogRef:
    apiGroup: postgresql.cnpg.io
    kind: ClusterImageCatalog
    name: camptocamp
    major: 18
  postgresGID: 999
  postgresUID: 999
  replica:
    enabled: true
    source: prod
  bootstrap:
    pg_basebackup:
      source: prod
  externalClusters:
  - name: prod
    connectionParameters:
      host: prod-rw
      user: streaming_replica
      sslmode: verify-full
    sslKey:
      name: prod-replication
      key: tls.key
    sslCert:
      name: prod-replication
      key: tls.crt
    sslRootCert:
      name: prod-ca
      key: ca.crt
kubectl apply -f lab4.yaml
5. Promote the replica cluster

Once the cluster is ready, check its recovery state then promote it:

kubectl cnpg psql prod-copy-blue -- -c "SELECT pg_is_in_recovery()"
kubectl patch cluster prod-copy-blue --type='merge' -p '{"spec":{"replica":{"enabled":false}}}'
kubectl cnpg psql prod-copy-blue -- -c "SELECT pg_is_in_recovery()"
6. Apply static masking

Finally, destroy sensitive information by applying static masking:

SELECT anon.anonymize_database();
7. Search for personally identifiable information
TABLE people;
