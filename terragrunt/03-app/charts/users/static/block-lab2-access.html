Goal: Install the tools, check that you can reach the cluster created in Lab 1, and open its Kubernetes Dashboard.
Windows users: run every command of this workshop in your WSL terminal (not PowerShell) and use the Linux instructions.

Install kubectl

# Linux / WSL (amd64)
curl -LO "https://dl.k8s.io/release/v1.35.8/bin/linux/amd64/kubectl"
chmod +x kubectl && sudo mv kubectl /usr/local/bin/

# macOS (Homebrew)
brew install kubectl
kubectl version --client

Check access to your cluster

Point kubectl to the kubeconfig saved at the end of Lab 1:

export KUBECONFIG=~/workshop/kubeconfig
kubectl get nodes
kubectl get pods -A

You should see one Ready node, plus running pods for applications.

Important: export only applies to the current terminal. Every time you open a new terminal, run export KUBECONFIG=~/workshop/kubeconfig again. If kubectl answers connection refused … localhost:8080, this variable is missing.

Install the kubectl-cnpg plugin

Install a 1.30.x version of the plugin, to match the operator deployed in your cluster.

The plugin is a single binary, kubectl-cnpg: download the archive for your platform from the GitHub releases (e.g. kubectl-cnpg_1.30.x_linux_x86_64.tar.gz), extract it and copy kubectl-cnpg to a directory of your PATH, such as /usr/local/bin.

Alternatives: the official documentation also provides an install script (curl … | sh), as well as .deb/.rpm packages and a Homebrew formula (brew install kubectl-cnpg, which installs the latest version).

Verify the installation:

kubectl cnpg version

Open the Kubernetes Dashboard

The Swisscom portal gives access to a Kubernetes Dashboard for your cluster:

  1. Go back to the Swisscom Portal and open your cluster page.
  2. Click Open Dashboard.

Use it to browse the namespaces, pods and resources created during the next labs.

Tip: Consider also installing k9s, a terminal UI to browse pods, logs and events without typing kubectl commands.
